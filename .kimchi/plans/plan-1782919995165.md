The fonts exist at `/mnt/c/Windows/Fonts/` — that's the **WSL mount** of `C:\Windows\Fonts`. But the `FONT_CANDIDATES` list has:

```js
'C:\\\\Windows\\\\Fonts\\\\arialbd.ttf',  // double-escaped in JS
'C:\\\\Windows\\\\Fonts\\\\segoeui.ttf',
'C:/Windows/Fonts/arialbd.ttf',
'C:/Windows/Fonts/segoeui.ttf',
```

These are **not** mapped to `/mnt/c/Windows/Fonts/` — they're `C:\...` which is **Windows** path notation, but the process is running in **WSL** (Linux) where `C:\` doesn't exist.

The `fileExists()` function does `fs.accessSync(p)` which tries to access these paths — they fail because the paths are Windows-style (`C:\...`), not Linux-style (`/mnt/c/...`).

So `findFont()` loops through all candidates:
1. `/usr/share/fonts/truetype/dejavu/DejaVuSans-Bold.ttf` — **doesn't exist** on this WSL system
2. `/usr/share/fonts/truetype/liberation/LiberationSans-Bold.ttf` — **doesn't exist**
3. `C:\\Windows\\Fonts\\arialbd.ttf` — **WSL doesn't see `C:\`**
4-6. Same — all fail

Result: `findFont()` returns `null` → `fontPath = null` → `fontArg = ''` → `drawtext` is called **without** a font → FFmpeg `drawtext` fails.

**This** is the root cause of "Oops, something went wrong while assembling your video."

## The fix

Add the **WSL mount path** (`/mnt/c/Windows/Fonts/...`) to the `FONT_CANDIDATES` list:

```js
const FONT_CANDIDATES = [
  '/mnt/c/Windows/Fonts/arialbd.ttf',
  '/mnt/c/Windows/Fonts/segoeui.ttf',
  '/usr/share/fonts/truetype/dejavu/DejaVuSans-Bold.ttf',
  '/usr/share/fonts/truetype/liberation/LiberationSans-Bold.ttf',
  'C:\\\\Windows\\\\Fonts\\\\arialbd.ttf',
  'C:\\\\Windows\\\\Fonts\\\\segoeui.ttf',
  'C:/Windows/Fonts/arialbd.ttf',
  'C:/Windows/Fonts/segoeui.ttf',
];
```

Put the `/mnt/c/...` paths first (highest priority) since the server runs on WSL.
